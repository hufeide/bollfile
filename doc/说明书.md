# bollfile 说明书

> 点对点（P2P）消息与文件传输工具，零配置自动互连。两台机器填**相同的房间码**即可自动发现并通信，无需配置 IP / 端口。
> 本文档说明“做了哪些事情、每一部分做什么”，作为代码地图与运行手册。

---

## 1. 总览与架构

bollfile 的设计借鉴了 bolloon 的“私密 topic + 自动发现 + 可靠单发”范式，但完全独立实现（不修改 bolloon 源码）。

整体分四层：

```
┌─────────────────────────────┐   表现层
│  renderer/ (React 对话框)    │   src/renderer/App.tsx
│  cli.ts (命令行驱动)         │   src/cli.ts
└──────────────┬──────────────┘
               │ IPC (仅 Electron)
┌──────────────▼──────────────┐
│  main/main.ts (Electron 主进程)│  main/preload.ts (安全桥)
└──────────────┬──────────────┘
               │ 组合 / 事件桥接
┌──────────────▼──────────────┐   应用层
│  core/index.ts → BollFileApp  │   把 传输/聊天/文件 三层组合起来
└──────────────┬──────────────┘
   ┌───────────┼───────────────┐
   ▼           ▼               ▼   协议层
core/chat.ts  core/filetransfer.ts   (presence / 聊天 / 文件分块)
   └───────────┼───────────────┘
               ▼
┌─────────────────────────────┐   传输层
│  core/transport.ts           │   HyperswarmTransport (DHT 发现 + 字节流)
│  core/local-bootstrap.ts     │   本地 DHT bootstrap (内网/离线增强)
│  core/framing.ts             │   长度前缀帧 (解决粘包)
└──────────────┬──────────────┘
               ▼
┌─────────────────────────────┐   身份层
│  core/keys.ts                │   持久身份 + Ed25519 签名/验签
└─────────────────────────────┘
```

## 2. 各模块说明（从底层到上层）

### 2.1 身份层 — `core/keys.ts`
**做什么**：管理每个“身份(role)”的稳定密钥，保证同一 role 跨重启身份不变（便于对方重连、历史归属）。
- `loadOrCreateKeys(role)`：在 `~/.bollfile/keys-<role>.json` 持久化两套密钥：
  - `swarmSeed`：32 字节 X25519 种子，喂给 hyperswarm 得到稳定路由身份（公钥即 `publicKey`）。
  - `edPrivate / edPublic`：Ed25519 密钥对，用于消息签名 / 验签（防伪造）。
- `sign(edPrivateHex, data)` / `verify(edPublicHex, data, sigB64)`：基于 Node 原生 `crypto` 的消息签名与验签。

### 2.2 传输层

#### `core/framing.ts` — 长度前缀帧
**做什么**：hyperswarm 的 `conn` 是裸字节流，多段消息会“粘包”。
- 帧格式：`[4 字节大端长度][payload]`。
- `encodeFrame(payload)`：封包；`FrameDecoder.push(chunk)`：按长度从流中切出完整帧数组（支持一次收到多帧或半个帧）。
- 聊天、文件协议都跑在这个“可靠的整条消息”之上，**不受 hyperswarm 64KB 单帧限制**，所以大文件能稳定传输。

#### `core/transport.ts` — `HyperswarmTransport`
**做什么**：基于 `hyperswarm` 实现“零配置自动发现 + 全双工字节流 + 可靠单发”。
- `joinRoom(roomCode)`：把房间码做 `sha256` 派生出**私密 topic**（房间码就是共享秘密，外人无法连入），调用 `swarm.join(topic)`，由公共 DHT 自动撮合。
- `connection` 事件：对方连入即按对方公钥（hex）记录连接，挂上 `FrameDecoder` 解析帧，向上发出 `peer` / `data` / `peer-offline` 事件（忽略自己）。
- `sendTo(pk, payload)`：直发一帧；`sendToWithWait(...)`：先直发，若暂无可发连接则等待对方经 topic 发现建连后再发，返回 `SENT` / `NO_CONN`（避免“消息进虚空”）。
- `broadcast(payload)`：向所有已连 peer 群发（用于 presence）。
- 支持两个增强选项（构造函数）：
  - `bootstrap`：显式 bootstrap 节点地址数组（用于私有/本地 DHT）。
  - `useLocalBootstrap`：自动起一个本地离线 DHT 节点作为 bootstrap（见 2.3）。

#### `core/local-bootstrap.ts` — 本地 DHT bootstrap（P6 内网/离线增强）
**做什么**：在局域网内起一个**真正离线**（`bootstrap:false`）的 DHT 节点（底层用 `dht-rpc`，因为 `hyperdht` 会把 `bootstrap:false` 又覆盖回公共节点），把它作为同局域网其他实例的 bootstrap 地址，使内网可**不依赖公共 DHT** 互连。
- `startLocalBootstrap()`：返回 `{ address: 'host:port', node, stop() }`，`address` 供 hyperswarm 的 `bootstrap` 选项使用。
- `HyperswarmTransport` 在 `start()` 时若 `useLocalBootstrap` 为真且未显式指定 bootstrap，就自动起它并把自己指向它；`stop()` 时一并销毁。
- 适用：有公网出口的普通内网 / 真实两机 LAN；**完全 air-gapped（无外网 + 离线 firewall）**场景下 hyperdht 的 NAT/holepunch 仍可能受限，需中继兜底（见第 7 节限制）。

### 2.3 协议层

#### `core/chat.ts` — `ChatProtocol`
**做什么**：基于传输层实现“在线状态 + 聊天消息 + 送达/已读回执 + 历史落盘”。
- **presence**：连接建立即互发 `{t:'presence', name, caps, pk, edPub}`，交换昵称与 Ed25519 公钥。
- **聊天消息** `chat.msg`：带 `id / ts / text / sig / edPub / name` 的 JSON；收端先 **验签**（失败发出 `verify-fail` 并丢弃），再 **去重**（防重复），随后落盘历史并回 `chat.ack`（送达回执）。
- **回执**：`chat.ack` → 触发 `delivered`；另有 `markRead` 发 `chat.read` → 触发 `read`。
- 历史：按对方公钥落盘到 `~/.bollfile/history/<pk>.jsonl`，`getHistory(peer)` 可回读。

#### `core/filetransfer.ts` — `FileProtocol`
**做什么**：基于传输层实现“文件 offer / 接受 / 分块 / 完成 / 断点续传”，含逐块与整文件校验。
- **协议消息**：`file.offer`（文件名/大小/分块数/整文件 sha256/mime）、`file.accept` / `file.reject`、`file.chunk`（帧内嵌 `[4字节头长][JSON头][二进制块]`，头含 `index` 与逐块 sha256）、`file.chunk.ack`、`file.done`、`file.resume`、`file.error`。
- **发送方**：先发 offer → 等 accept（30s 超时，否则视为拒绝）→ 滑动窗口（窗口 32 块）流水线发块 → 收 ack 推进 → 发 done。
- **接收方**：写临时文件 `<id>.part` + 元数据 `<id>.meta.json`（记录已收分块）；每块先 **逐块 sha256 校验**，错误发 `file.error`；收齐全后 **整文件 sha256 校验**，通过才 rename 到下载目录（重名自动加 `(1)` 等）。
- **断点续传**：收到 offer 时若已有同 sha256/size 的 `.part`+`.meta`，计算已连续收到的最大块，发 `file.resume` 让发送方从断点续发；发送方 `onResume` 调整起点。
- 目录：`downloadDir`（默认 `~/.bollfile/downloads`，CLI 用 `--download` 指定）；`autoAccept=true` 时自动接收。

### 2.4 应用层 — `core/index.ts` — `BollFileApp`
**做什么**：把 传输层 + 聊天协议 + 文件协议 组合成一个对象，并把所有子协议事件统一桥接为 app 级事件，供 CLI / Electron 直接监听。
- 构造：`new BollFileApp({ role, name, downloadDir, historyDir, autoAccept, useLocalBootstrap, transport })`；不传 `transport` 时默认用 `HyperswarmTransport`。
- `bridge()`：把底层 `peer/peer-offline`、聊天 `peer-status/message/delivered/read/verify-fail`、文件 `file-incoming/file-progress/file-completed/file-rejected/file-error/file-resume/file-offer-sent` 全部 `emit` 到 app 上。
- 对外方法：`start()`、`joinRoom(code)`、`setName()`、`sendMessage(pk,text)`、`sendFile(pk,path)`、`acceptFile(id)`、`rejectFile(id)`、`getPublicKey()`、`getPeers()`、`getHistory(peer)`、`stop()`。
- `TransportLike` 接口：hyperswarm 与测试替身都实现它，保证可替换。

### 2.5 表现层

#### Electron 桌面应用
- **`src/main/main.ts`**：Electron 主进程。启动 `BollFileApp`（真实 hyperswarm 传输），通过 `ipcMain.handle` 暴露 `start / joinRoom / sendMessage / sendFile / acceptFile / rejectFile / pickFile(文件选择对话框)` 等，并把 app 事件经 `win.webContents.send('app-event', {type,data})` 推给渲染进程。
- **`src/main/preload.ts`**：用 `contextBridge` 在隔离上下文里暴露最小安全 API `window.electronAPI`（所有调用走 `ipcRenderer.invoke` / `on`），不开启 `nodeIntegration`。
- **`src/renderer/main.tsx`**：React 入口，`createRoot` 挂载 `<App/>`。
- **`src/renderer/App.tsx`**：React 对话框 UI。
  - 起始页：填昵称、房间码（可随机生成）、role（同机多开区分）。
  - 主界面：左侧同伴列表（自动出现、在线绿点）、右侧消息气泡（我方靠右蓝、对方靠左）、📎 发文件、对方发来的文件以卡片形式出现，可“接收/拒绝”，传输进度条实时更新，完成显示保存路径。
  - 通过 `electronAPI.onEvent` 订阅所有事件并驱动 React 状态。
- **`src/renderer/index.html`**：承载 UI 的页面（含 CSP、内联样式），打包后由主进程 `loadFile` 加载，引用 `renderer.js`（由 esbuild 生成）。

#### 命令行 — `src/cli.ts`
**做什么**：无显示器也能在服务器/两台机器上实测。
- 参数：`--room <码> --name <昵称> [--role <role>] [--download <目录>] [--local-bootstrap]`。
- 进入交互式命令：`peers`（列出同伴）、`msg <pk> <文本>`、`file <pk> <路径>`、`help`、`exit`。
- 默认 `autoAccept=true`，收到的文件自动存到下载目录。

### 2.6 测试替身 — `src/test-support/loopback-transport.ts`
**做什么**：用 Node `Duplex` 流把两个 `BollFileApp` 直接相连，**复用真实的 framing / Chat / File 代码**，从而确定性地测试上层协议，不必依赖外部 DHT（沙箱可跑）。
- `LoopbackTransport`：实现 `TransportLike`，内部用 `encodeFrame`/`FrameDecoder` 走真实分帧。
- `link(a, b)`：把 a、b 互相用全双工流连接，触发双方 `peer` 事件。

## 4. 构建与运行

### 依赖与脚本（`package.json`）
- `build`：`tsc` 编译 TS → `dist/`；`esbuild` 把 `src/renderer/main.tsx` 打包为 `dist/renderer/renderer.js`；拷贝 `index.html`。
- `start`：`electron .`（启动桌面 GUI）。
- `dev`：`build` 后 `electron .`。
- `cli`：`build` 后 `node dist/cli.js`。
- `test`：`tsc` 后 `node --test dist/test/`。

### 安装
```bash
cd bollfile
# 跳过 electron 二进制下载（仅取类型用于编译；跑 GUI 时需正常安装）
ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm install
npm run build
```

### 运行 GUI
```bash
npm start            # 需正常安装 electron + 有显示器
```
两机分别打开，填**相同房间码** → 自动互连。

### 运行 CLI
```bash
# 机器 A
node dist/cli.js --room SECRET --name A
# 机器 B
node dist/cli.js --room SECRET --name B
```
进入后输入 `peers` / `msg <pk> <文本>` / `file <pk> <路径>`。

## 6. 内网 / 离线：本地 DHT bootstrap

默认“零配置”依赖**公共 DHT**（两台公网机器、或有公网出口的普通内网都可用）。若要在**不依赖公共 DHT** 的内网里互连，启用本地 bootstrap：
```bash
# CLI
node dist/cli.js --room SECRET --name A --local-bootstrap
# Electron：在 main.ts 构造 BollFileApp 时传 { useLocalBootstrap: true }
```
局域网内各实例自动以本地 bootstrap 互连。详见 `core/local-bootstrap.ts` 与 `transport.ts` 的 `useLocalBootstrap`。

## 7. 已知限制与后续

- **公共 DHT 隐私**：topic 由房间码 `sha256` 派生，房间码即“共享秘密”，泄露等于可被连入；请使用随机/强房间码。
- **公网入站端口**：hyperswarm 监听端口需被放行（云安全组），否则对方无法拨入；可让一方主动发现/拨出缓解。
- **完全 air-gapped（无外网 + 离线 firewall）**：当前 hyperswarm/hyperdht 的 NAT/holepunch 限制在纯离线同机/受限场景下可能连不上。已实现的“本地 DHT bootstrap”覆盖“有公网出口的内网 / 真实两机 LAN”，但**彻底离线的中继兜底（P6：libp2p / iroh relay）** 尚未实现，按需再加。
- **Electron GUI 运行**：本环境跳过 electron 二进制，GUI 需正常安装 electron 并具备显示器后方可 `npm start`。

## 9. 历次改动记录（会话追加 · 排障与跨机器连接）

> 本章记录每次改动的**根因 + 做法 + 关键坑**，供下次快速定位。

### 9.1 中文乱码修复

**根因**：页面中文显示成方块/乱码，不是编码问题（`index.html` 已声明 `<meta charset="UTF-8">`），而是
(1) 系统**完全没有中文字体**；`fc-list | grep -i cjk` 无输出；
(2) `font-family` 里只有 `-apple-system, "Segoe UI", Roboto, "PingFang SC"`，这些在 Linux/WSL 下不存在且**没有中文回退**，Chromium 无字形可渲染。

**做法**：
- 非 root 装字体：从 Ubuntu 镜像 `apt-get download fonts-wqy-microhei` 拿到 `.deb` → `dpkg-deb -x` 解压 → 把 `wqy-microhei.ttc` 拷到 `~/.local/share/fonts/` → `fc-cache -f` 刷新。
- 在 `index.html` 的 `font-family` 增加中文回退：`"Microsoft YaHei", "WenQuanYi Micro Hei", "Noto Sans CJK SC", "WenQuanYi Zen Hei"`。
- **必须重启 Electron 窗口**才生效（`fontconfig` 启动读取）。

### 9.2 `.gitignore` 补全

原因：原 `.gitignore` 只忽略 `dist/`、`node_modules/`，太少。
补全为合理规则（构建产物/日志/密钥/编辑器/IDE 本地数据）：
- 忽略：`dist/`、`node_modules/`、`*.tsbuildinfo`、`*.log`、`npm-debug.log*`、`coverage/`、`.cache/`、`*.pem *.key *.crt *.p12 .env .env.*`、`.DS_Store`、`Thumbs.db`、`.vscode/`、`.idea/`、`.codebuddy`（**不带尾斜杠**才稳妥）。
- 仍提交：`src/`、`package.json`、`package-lock.json`、`tsconfig.json`、`README.md`、`实施计划.md`、`doc/`、`note/`、`start-gui.sh`。
- 密钥文件实际生成于 `$HOME/.bollfile/`（仓库外），本就无需处理；`.gitignore` 的密钥规则是保险。

### 9.3 中文字体随应用打包（跨机器生效）

**目标**：换机器无需手动装字体，Win/Mac/Linux 都能渲染中文。

**做法**：
- 把 `wqy-microhei.ttc`（~5.1MB）放进仓库 `src/renderer/fonts/`（随 git 提交；`.gitignore` 没忽略 `*.ttc`，已确认会被提交）。
- `index.html` 增加 `@font-face`，从打包目录 `fonts/wqy-microhei.ttc` 加载：
  ```css
  @font-face {
    font-family: 'WenQuanYi Micro Hei';
    src: url('fonts/wqy-microhei.ttc') format('truetype');
    font-display: swap;
  }
  ```
- CSP 放开 `font-src 'self'`：
  `content="default-src 'self'; style-src 'self' 'unsafe-inline'; script-src 'self'; font-src 'self'"`。
- `package.json` 的 `build` 脚本增加 `fs.cpSync('src/renderer/fonts','dist/renderer/fonts',{recursive:true})`，构建产物 `dist/renderer/fonts/` 含字体。
- 想减小仓库体积可改用 `.woff2`（约 1/3 大小），相应改 `format('woff2')`。

### 9.4 跨机器连接：局域网直连 + 公网兜底

**背景**：用户同局域网（同一 WiFi/路由器）两台机器填相同房间码却“没有同伴”。
**根因**：Hyperswarm 公共 DHT 给的是各自“公网地址”，同路由器下多数不支持 NAT 回环（hairpin），互相连不通。
**目标**：局域网能直连；同时保留公网 DHT（不同网络靠 UDP 打洞）。两条路互补。

**改动清单**：

1. **新建 `src/core/lan-discovery.ts`** — 局域网多播发现。
   - 多播组 `239.255.42.42`，端口 `49740`，TTL 1（仅同网段）。
   - 每 2s 广播 JSON `{ v:1, r:<房间码sha256前8字节hex>, a:{host,port}, p:<自身公钥hex> }`；收到同房间、非自身地址即回调 `onPeer({host,port,pk})`。
   - 发送/接收都绑定到监听网卡地址；`getLanIp()` 取第一个非内部 IPv4。

2. **`src/core/transport.ts`**：
   - 新增 `startLanDiscovery(roomCode)`：拿到监听端口后启动 `LanDiscovery`；发现对端即**直接对指定 LAN 地址握手直连**。
   - ⚠️ **关键坑（下次必记）**：hyperswarm v4 **没有**公开的 `swarm.connect(host:port)` 也没有 `swarm.address()` 方法（只有 `joinPeer(publicKey)` 仍走 DHT 查地址，绕不开回环）。所以：
     - 监听端口用 `(this.swarm as any).server.address().port`（hyperdht server 的 `address()` 返回 `{publicKey, host, port}`，host 常为 `0.0.0.0`，故广播 host 用 `getLanIp()`，端口用这里的 `port`）。
     - 直连用底层 hyperdht：
       ```ts
       const conn = (this.swarm as any).dht.connect(Buffer.from(key,'hex'), {
         keyPair: (this.swarm as any).keyPair,                 // 种子派生 keyPair = 服务端身份(见下)
         relayAddresses: [{ host: peer.host, port: peer.port }] // 指定地址即“直连目标”
       });
       ```
     - 原理：hyperdht `connect` 的 `relayAddresses` 会被当作直连目标做 peer 握手；对端 hyperswarm server 收到握手后由 `_handleServerConnection` 正常触发 `connection` 事件（其身份即 `server.listen(this.keyPair)` 用的种子派生 keyPair，验签一致）。**已本地双实例端到端验证**（`aP=1 bP=1`）。
   - 新增 `lanTried` 集合去重（同一 pk 只发起一次直连），同伴掉线（`conn close`）时清除以便重连。
   - `stop()` 清理 `lan`。
   - 新增 `BOLLFIlE_BOOTSTRAP` 环境变量支持：逗号分隔 `host:port`，指向**可达的 DHT bootstrap**（公网默认节点不可达时兜底，例如某些地区连不上公共 bootstrap）。

3. **`src/core/index.ts`**：`TransportLike` 接口加 `startLanDiscovery(code)`；`BollFileApp` 加 `startLan(code)` → `this.transport.startLanDiscovery(code)`。

4. **`src/test-support/loopback-transport.ts`**：补 `startLanDiscovery()` 空实现（测试替身不依赖发现）。

5. **`src/main/preload.ts`**：暴露 `startLan: (code) => ipcRenderer.invoke('startLan', code)`。
   **`src/main/main.ts`**：`ipcMain.handle('startLan', ...)` → `boll?.startLan(code)`。
   **`src/renderer/App.tsx`**：进入房间后 `await api.joinRoom(...)` 之后 `await api.startLan(...)`（公网 + 局域网双路同时启动）。

**端到端验证（本地，不必依赖多播环境）**：
- 核心握手：`dht.connect(pk,{keyPair,relayAddresses})` 在两台同机实例间互连成功（`a sees peer`/`b sees peer`）。
- 完整多播：两个 `HyperswarmTransport` 都 `joinRoom`+`startLanDiscovery` 同房间，9s 内互相出现同伴（`aP=1 bP=1`）。

**上线须知**：
- 两台机器需在同一子网（多播不过 VLAN/跨网段）；跨网段/不同网络走公网 DHT。
- 每台机器防火墙需放行该应用（直连走 UDP，hyperswarm 监听端口为随机端口）；否则可能连不上。
- 若仍看不到同伴，多半是防火墙挡 UDP，先放行再试。
- 若公网 DHT 默认节点不可达：跑一个自建 bootstrap 节点，用 `BOLLFIlE_BOOTSTRAP=host:port npm start` 指向它（后续可加“一键起 bootstrap 节点”脚本）。

### 9.5 打包 Windows 原生版（跨机器部署 · 根治 WSL2 网络隔离）

**背景**：GUI 之前在 WSL2 里跑（IP `172.28.x` 虚拟网段），与另一台机器的真实局域网不在同一网络平面 —— 多播出不了 WSL 虚拟交换机、对端 `172.28.x` 地址被宿主 NAT 挡住直连不进去。根治办法是**在 Windows 原生运行 GUI**（真实 `192.168.x` 局域网），两台都原生运行即同平面、可多播/直连。

**做法**：
- 安装 `electron-builder`（加入 devDependencies）。
- `package.json` 加 `build` 字段：
  - `win.target = ["zip","dir"]` —— 免 wine，可在 Linux/WSL 交叉打包（NSIS 安装包需 wine，故不用）。
  - `asarUnpack: ["**/*.node","**/prebuilds/**"]` —— `sodium-native`/`udx-native` 是 native 模块，必须放 asar 外，否则运行时 `require` 失败。
  - `files: ["dist/**/*","package.json","!dist/test/**","!dist/test-support/**"]`。
- 加脚本 `"pack:win": "npm run build && electron-builder --win --x64"`。
- 打包命令（用国内镜像加速 electron 二进制；开发时用的 `ELECTRON_SKIP_BINARY_DOWNLOAD=1` 在打包时必须取消，否则 electron 二进制下不来）：
  ```bash
  unset ELECTRON_SKIP_BINARY_DOWNLOAD
  ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm run pack:win
  ```
- electron-builder 会自动 `@electron/rebuild`，按 electron 的 ABI 重新获取 native 依赖的 `win32-x64` prebuild，无需手动 rebuild。

**产物**：`release/bollfile-0.1.0-win.zip`（115MB，整目录压缩）与 `release/win-unpacked/`（含 `bollfile.exe`）。

**校验要点**：`asar` 内应无 `.node`；`app.asar.unpacked/node_modules/{sodium-native,udx-native}/prebuilds/win32-x64/*.node` 必须存在（已确认）。

**部署注意**：
- 免安装版：把 `win-unpacked` 整目录（或解压 zip）拷到 Windows，双击 `bollfile.exe`。
- **首次运行 Windows 防火墙会弹窗，必须“允许（专用网络）”**，否则 UDP 多播(49740)/hyperswarm 随机端口被挡，仍连不上。
- 未签名：SmartScreen 可能报“未知发布者”，点“仍要运行”即可；要正式安装向导(NSIS)需 wine 或在 Windows 上打包。
- **两台机器都要在 Windows 原生运行**（不要在其中一台的 WSL2 里跑），才能处于同一局域网平面。

### 9.6 新建 bollweb（网页版 P2P，复用 bolloon 已通技术）

**背景**：electron 版在 WSL2 下 LAN 多播/直连不通（多播出不了 WSL 虚拟交换机，对端 `172.28.x` 被宿主 NAT 挡）；且发现 **bolloon 的 P2P 底层也正是 hyperswarm**（其 `src/network/p2p-direct.ts` 是 hyperswarm 薄包装，靠公共 DHT 私密 topic 自动发现），并且 bolloon 已验证能通。故放弃 electron 的 LAN 多播方案，改用 bolloon 的 P2P 技术做纯网页版（浏览器跑不了 hyperswarm，需 Node 后端代持）。

**做法（独立项目 `/home/fei/workspace/bollweb`）**：
- `package.json`：ESM，依赖 `hyperswarm` / `ws` / `b4a`（与 bolloon 同库）。
- `server.js`：复用 bolloon `P2PDirect` 的 hyperswarm 配置——默认公共 DHT、`joinTopic(房间码)` 私密 topic 自动发现、`seed` 持久化身份（`~/.bollweb-secret.json`），**去掉**安全扫描/known-peers；加 WebSocketServer 桥接 + 静态托管（`public/`）。
- `public/`：`index.html` + `app.js` + `style.css`。前端经 `localhost` WS 连后端；聊天即时显示；文件分块（64KB，base64）经 WS→后端→hyperswarm 广播给同伴，对端重组为 Blob 提供下载。
- 协议：前端↔后端用 WS JSON（`type`/`k` 字段）；后端之间 hyperswarm 明文 JSON。

**已验证**：`server.js` 启动（hyperswarm native 模块 OK）、静态托管 `200`、WS 桥接（`ready`/`peers` 消息）均通过；P2P 跨机互连需在真实两台机器测（同 bolloon 环境，应可通）。

**运行**：两台机器各 `cd bollweb && npm install && npm start`，浏览器开 `http://localhost:8080`，填**相同房间码**即可互发消息/传文件。详见 `bollweb/README.md`。

**注意**：房间码即共享秘密（泄露=可连入）；首次运行允许防火墙（hyperswarm 用 UDP）；electron 版 `bollfile` 保留未删，仅暂停。
