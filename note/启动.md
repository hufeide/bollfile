问题不是 Electron，而是 Xvfb 本身在初始化 GLX 时崩溃——你的环境是 WSL + NVIDIA 驱动，Xvfb 去加载 D3D12/WSL 的 NVIDIA DRI 驱动时直接段错误（backtrace 里全是 libnvwgf2umx.so / libD3D12Core.so / swrast_dri.so）。

解决办法：启动 Xvfb 时禁用 GLX 扩展，并用软件渲染。试一下：

用禁用 GLX 的方式启动 Xvfb 避免 NVIDIA DRI 段错误

cd /home/fei/workspace/bollfile && pkill Xvfb 2>/dev/null; rm -f /tmp/.X11-unix/X99 2>/dev/null; Xvfb :99 -screen 0 1280x1024x24 -extension GLX > /tmp/xvfb2.log 2>&1 & sleep 3; echo "Xvfb pid: $!"; echo "---log---"; cat /tmp/xvfb2.log; echo "---sockets---"; ls -la /tmp/.X11-unix/ 2>/dev/null
深度思考
Xvfb 现在成功启动了（:99 socket 已建立，只有那个无害的 ownership 警告）。现在用这个虚拟显示跑 Electron，并强制软件渲染、关闭沙箱：

在虚拟显示下以软件渲染启动 electron 应用

cd /home/fei/workspace/bollfile && DISPLAY=:99 LIBGL_ALWAYS_SOFTWARE=1 ELECTRON_DISABLE_SANDBOX=1 npm start 2>&1 | head -40
后台运行


# 启动虚拟显示器（禁用 GLX 避免 NVIDIA/WSL 驱动崩溃）
Xvfb :99 -screen 0 1280x1024x24 -extension GLX > /tmp/xvfb.log 2>&1 &
# 运行应用
cd /home/fei/workspace/bollfile
DISPLAY=:99 LIBGL_ALWAYS_SOFTWARE=1 ELECTRON_DISABLE_SANDBOX=1 npm start

问题根因
你刚才那次启动失败，是因为：我们禁用了 Xvfb 的 GLX 扩展后，Electron 的 ANGLE 图形层默认先去尝试 GLX 后端，找不到就直接退出 GPU 进程（日志里 GLX is not present → Exiting GPU process due to errors during initialization）。而我的测试加上 --use-angle=swiftshader 后，强制走 SwiftShader 软件渲染后端，所有 GLX 错误消失，应用正常起来。

以后怎么启动
先在你终端里 Ctrl-C 停掉当前那个 GPU 已退出的会话。
用新脚本一键启动：
bash
cd /home/fei/workspace/bollfile
./start.sh
脚本会自动：检测并启动 Xvfb 虚拟显示器（禁用 GLX）→ 用 SwiftShader 软件渲染启动 Electron。

日志里剩下那些报错要不要管？
Failed to connect to the bus / dbus —— 无害，headless 环境没有系统 D-Bus 总线，不影响功能。
只要不再出现 GLX is not present 和 Exiting GPU process，就说明图形层已经正常工作了。
